Estrategia

La extensión hace de «FoxyProxy automático»: fija el proxy del navegador con la API de extensiones (chrome.proxy / browser.proxy) y responde sola al 407 vía onAuthRequired. Sin VPN, sin tocar la configuración del sistema.

Los bugs reales que arreglamos

  • v1.0.0→v1.0.4 — el proxy nunca se aplicaba en Chrome nuevo: la detección de Firefox usaba typeof browser; Chrome ≥131 define ese alias también en MV3, así que la extensión entraba en la rama Firefox y pasaba a chrome.proxy.settings.set un objeto con proxyType (inválido) → «Invalid invocation» silencioso → el navegador seguía en modo system y veías tu IP real con la red encendida. Corregido en v1.0.4 con el criterio canónico runtime.getBrowserInfo (solo existe en Firefox).
  • FoxyProxy pisa el ajuste: el último que escribe gana. Un poll con chrome.alarms cada minuto compara levelOfControl y las reglas; si otra extensión las cambió, re-fija las nuestras y marca el badge «¡» con explicación; el popup muestra el banner con el diagnóstico.
  • El registro anti-muerte: onAuthRequired se añade con asyncBlocking en Chromium y con la forma de promesa en Firefox; si un navegador no soporta la primera, cae a la segunda en vez de morir el script.
  • Firefox MV2: empaquetado (xpi) listo para firmar en AMO; la carpeta firefox/ para carga temporal.

El popup dice la verdad

Al abrirlo: consulta tu cuenta (/login + /me) para saber si la red está encendida y qué IP de salida espera, y hace un fetch real vía el proxy del navegador a api.ipify.org: si coincide con la esperada, verde «✓ es la de tu circuito»; si no, te muestra ambas IPs y el diagnóstico. El badge en la barra (✓/✕/¡) hace lo mismo sin abrir el popup.
