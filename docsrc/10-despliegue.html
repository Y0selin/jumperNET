Despliegue y operación

Todo vive en ~/jumpernat del VPS y se controla con docker-compose. En esta sección: la pila completa, TLS, el WordPress de documentación, los artefactos del navegador y las rutinas de operación.

La pila (docker-compose.yml)

sudo docker compose ps      # caddy, api, entrada, entrada-http,
                            # nodo1..nodo6, wp, wp_db
sudo docker compose up -d --build api   # reconstruir solo la API
  • .env: INTERNAL_TOKEN, PEER_TOKEN, JWT_SECRET, CLAVE_SALTOS, DB_PATH… (fuera de git; plantilla en .env.example).
  • Volúmenes: data/jumpernat.db (API), base del wp_db, descargas/ (binarios del navegador que se sirven por el panel), docsrc/ (fuentes de esta documentación).
  • La API escucha SOLO en 127.0.0.1:8000; el mundo entra por Caddy.

TLS y rutas (Caddy 2.8)

  • jumpernet.duckdns.org: certificado automático de Let's Encrypt (test 4.1 verifica el handshake real).
  • /api/* → API (strip del prefijo, headers de proxiado con X-Forwarded-For).
  • /docs/* → WordPress interno (strip de /docs/; WP_HOME/WP_SITEURL fijados con la subruta).
  • SOCKS5 (1080) y HTTP (1081) publicados directo (no pasan por Caddy: son protocolos de bytes, no HTTP).

El WordPress de documentación

# contenedores wp + wp_db en la misma red interna
sudo docker exec jumpernat-wp-1 php /tmp/wp.phar --allow-root \
     --path=/var/www/html post list --fields=ID,post_name

# el contenido fuente vive en /tmp/docsrc (dentro del contenedor wp):
# 00-indice … 12-changelog. Reconstruir todo:
sudo bash ~/build_blog5.sh     # (borra posts/crea publicados/ajusta portada)
  • Credenciales admin en el fichero privado del repo (cámbialas desde wp-admin).
  • La portada es una PÁGINA (show_on_front=page) con el índice en orden de lectura.

Artefactos del navegador (release)

  • Cada build produce 5 ficheros en deploy/navegador/salida/: JumperNET Browser Setup 1.0.0.exe (NSIS), JumperNET Browser 1.0.0.exe (portable, se sube como jumpernet-navegador-portable.exe), jumpernet-navegador-windows.zip, JumperNET-1.0.0.AppImage y jumpernet-navegador-linux.zip.
  • Se suben con rsync a ~/jumpernat/descargas/ y el panel los ofrece en «Descargas» (con LEEME-navegador.txt y notas-release.md).
  • Verificación de integridad tras subir: md5 local vs remoto (obligatorio antes de dar por terminado un release).

Backups y límites

  • Backup del estado: sqlite3 data/jumpernat.db ".backup backups/$(date +%s).db" (carpeta backups/ con snapshots por timestamp).
  • Límites de cada contenedor: nodos 96m/0.25 cpu; API 256m (argon2 necesita RAM). La web estática del panel va aparte (GitHub Pages), no carga el VPS.
  • MariaDB: buffer pool fijado 48M (la carrera de arranque y el wp-config con escapes del heredoc dieron la clásica «Error establishing a database connection» intermitente — ver diario).
