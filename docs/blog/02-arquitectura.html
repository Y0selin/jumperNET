El mapa completo

De/sde el punto de vista de una petición, la red tiene ocho piezas.Todas viven en el mismo VPS (Oracle Cloud, Ubuntu) dentro de una red Docker privada llamada red_jumper, y solo cuatro puertos están expuestos: 80, 443 (HTTPS/Caddy), 1080 (SOCKS5) y 1081 (HTTP proxy).

1. La API (FastAPI, python)

Es el cerebro: guarda usuarios (argon2), decide circuitos, lleva el registro de nodos vivos por heartbeat, sirve los endpoints internos para los proxies y expone los públicos para el panel. Solo escucha en la red interna (api:8000); Caddy es su puerta de entrada HTTPS.

2. Caddy

El guardián de HTTPS: certificado Let's Encrypt automático, proxy inverso a la API, y dos rutas especiales: /bajares/* (ficheros estáticos: zips del navegador) y /docs/* (este sitio, WordPress en un contenedor aparte). Todo lo demás que llega al dominio es API.

3. Entrada SOCKS5 (puerto 1080)

El proxy con el que se navega "a mano" (curl, scripts). Autentica al usuario con Basic (email+password) contra la API, comprueba el circuito, valida destino (puertos 80/443 y nada de IPs privadas/metadata) y abre la cadena de saltos.

4. Entrada HTTP (puerto 1081)

El mismo corazón, pero hablando proxy HTTP con CONNECT. Existe porque los navegadores no dejan autenticar SOCKS5 desde extensiones: sí capturan el 407 del proxy HTTP vía onAuthRequired. Es la puerta que usan la extensión y el navegador dedicado.

5-7. Los nodos (nodo1..nodoN)

Contenedores idénticos (jumpernat/nodo) en el puerto interno 9000. Cada uno habla un protocolo minimalista: primera línea = ruta de saltos restantes separada por comas; si quedan saltos conecta al siguiente; si es el último (exit) conecta al destino final. Los nodos intermediarios son de reenvío ciego. Todos mandan heartbeat a la API cada 10 s; muertos no entran en nuevos circuitos.

8. El exit implícito

El tercer salto conecta al destino y reenvía. Si hay cifrado JENC activado, el exit además descifra el stream entrante y cifra las respuestas de vuelta (ver el post del JENC).

El flujo de una petición real

TÚ ──▶ HTTPS 443 (Caddy) ──▶ API (solo gestión)
TÚ ──▶ SOCKS5 1080 ─┐
TÚ ──▶ HTTP 1081 ──┴─▶ nodo₁ ──▶ nodo₂ ──▶ nodo₃ (exit) ──▶ internet (solo 80/443)

Elección del circuito

Cuando pulsas ACTIVAR, la API elige tres nodos distintos entre los vivos y guarda el circuito en tu usuario. La entrada no elige: le pide a la API el circuito de las credenciales. Cada redesviación «girar» (ROTATE) reconstruye el circuito con otros nodos — como el New Circuit de Tor.

Resiliencia

Los órganos internos no comparten memoria: si un nodo cae los circuitos nuevos lo omiten (el último heartbeat contó), y las conexiones ya abiertas mueren limpio. El panel lo reflecta: lista de nodos con estado, latencia TCP medida y conexiones crrentes.
