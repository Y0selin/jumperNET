El diario de incidencias

Estos problemas aparecieron de verdad durante el desarrollo. Cada uno con su síntoma, la causa de raíz y la solución, para que cualquier persona que retome el código no repita el viaje.

1. «Veo mi IP real con la red encendida» (la más importante)

  • Síntoma: el popup / la página ipify mostraba la IP del cliente con el circuito activo.
  • Causa raíz: doble. (a) En Chrome ≥131 el alias browser existe y la extensión aplicaba el ajuste Firefox-erróneo (post de la extensión). (b) En el navegador Electron, el <webview> usa su propia sesión (persist:jn): el proxy solo estaba en la sesión por defecto, así que las pestañas navegaban directo.
  • Solución: detección canónica de Firefox + aplicar el proxy a TODAS las sesiones.

2. El mapa «API KEY REQUIRED»

  • Síntoma: el mapa del panel mostraba la imagen del error del proveedor de tiles.
  • Causa: los tiles de Carto responden HTTP 200 con la imagen del mensaje; el antiguo detector tileerror nunca disparaba (no hay error HTTP).
  • Solución: se retiró el proveedor: el mapa se pinta siempre con un GeoJSON vectorial de países servido desde el propio panel (mundo.json), sin tiles, claves ni terceros.

3. HTTP plano muerto con JENC activado

  • Síntoma: curl http://example.com por el proxy devolvía «Empty reply»; https:// funcionaba.
  • Causa: en la entrada HTTP, la petición GET se escribía en claro ANTES de la magia; el exit leía "GET " como prefijo, no reconocía JENC y el stream quedaba partido (el exit no respondió en modo JENC en logs).
  • Solución: la petición inicial ahora viaja como PRIMER registro JENC dentro del mismo emisor (ver post JENC). Verificado: http y https 200 por el circuito.

4. Nodos muertos rompen circuitos en silencio

  • Симптом: circuitos con un hop caído morían a mitad sin mensaje útil.
  • Solución: testo de heartbeat (10 s) + la entrada descarta del mapa a los nodos sin latido antes de construir el circuito.

5. Registro con límite anti-spam

  • Síntoma: «429» al registrar contas de prueba.
  • Solución (doc): es una ventana por IP: en desarrollo se reinicia la API para vaciarla; en producción se espera o se limpia manual.

6. WordPress con «Error establishing a database connection» repentina

  • Esperienca real: el primer comando tras instalar funcionó y el segundo falló; causa: el eval de wp-config con escapes del heredoc (documentado en el post de despliegue) y la carrera de arranque de MariaDB al primer segundo.
  • Solución: bloque limpiar sin escapes + recrear el contenedor; hypertiniendo default mysqlclient varía — fijado nn buffer pool 48M.
